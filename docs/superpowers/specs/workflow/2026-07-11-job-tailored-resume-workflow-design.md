# 岗位定制简历工作流设计

## 目标

新增一个官方只读工作流模板，将用户已有的主简历和目标岗位 JD 转换为一份可投递的岗位定制简历。模板必须保留事实、解释每项调整，并在证据不足时询问用户，不能编造经历、技能或量化数据。

现有“简历生成 (HTML)”继续负责从工作目录整理通用简历；新模板只负责针对具体岗位进行匹配、取舍和改写。

## 输入与输出

输入来源：

- 工作目录中的主简历，优先读取 `resume.md`、`resume.tex`、`resume.txt` 和可解析文本文件。
- 用户在工作流任务描述中粘贴的目标岗位 JD，或工作目录中的 JD 文本文件。
- 可选的项目代码、Git 历史和补充材料，只能用于验证用户真实完成的工作。

最终输出到工作流 output 目录：

- `tailored-resume.html`：单栏、易解析、可直接打印的岗位定制简历。
- `tailored-resume.md`：便于用户继续编辑的内容版本。
- `match-report.md`：岗位要求、对应证据、未覆盖项和主要改写说明。

不输出不可解释的 ATS 百分比分数。

## 工作流图

```text
start
  |-- analyze-job ---------|
  |                        v
  |-- extract-resume --> match-evidence --> clarify-gaps --> tailor-resume
  |                                                   |             |
  |                                                   |             v
  |                                                   |--------> review
  |                                                                    |
  `------------------------------------------------------------------> end
```

节点职责：

1. `analyze-job`：提取岗位职责、硬性要求、加分项、技术关键词和优先级，产出结构化 JD 分析。
2. `extract-resume`：提取主简历中的经历、项目、技能和量化成果，保留原始事实与来源位置。
3. `match-evidence`：建立“岗位要求 -> 简历证据”映射，区分强匹配、可改写和无证据，不直接写最终简历。
4. `clarify-gaps`：仅当关键要求可能有真实经历但证据不足时调用 `workflowGate.ask(...)`；用户回答后把补充内容标记为用户提供事实。没有必要询问时直接继续。
5. `tailor-resume`：按岗位优先级重排内容，改写为动作、方法、结果结构，自然使用 JD 术语，生成 Markdown 和固定单栏 HTML。
6. `review`：独立检查事实一致性、关键词堆砌、重复内容、篇幅、HTML 占位符和输出文件；发现问题时直接修正后再完成。

## 固定资产

模板目录包含：

- `workflow.json`：官方工作流定义和固定节点图。
- `resume-template.html`：无个人数据的单栏 HTML 模板。
- `tailoring-guidelines.md`：事实约束、岗位匹配规则和 bullet 写作标准。
- `review-checklist.md`：最终审查清单。

官方模板的节点、边和固定资产不可修改；用户仍可为允许配置的 agent 节点选择 Runtime/Agent 配置并调整 prompt 补充内容。

## 错误处理

- 找不到主简历：`extract-resume` 明确列出已检查路径，并通过 Gate 要求用户提供文件位置。
- 找不到 JD：`analyze-job` 通过 Gate 要求粘贴 JD 或提供文件路径。
- JD 信息不足：按已有内容生成，但在 `match-report.md` 标明限制。
- 缺少岗位要求证据：保留为未覆盖项，不推断、不编造。
- HTML 渲染失败：Markdown 和匹配报告仍需保留，review 节点报告具体失败原因。

## 验收标准

- 应用能发现并加载该官方工作流，且不影响现有简历工作流。
- 固定资产 token 在加载时全部替换，最终 prompt 不残留资产占位符。
- 图结构有效，所有非结束节点可到达结束节点。
- 工作流明确禁止虚构事实和虚假 ATS 分数。
- 输出要求同时包含 HTML、Markdown 和可解释的匹配报告。
- 测试覆盖模板加载、资产注入、节点/边结构和关键安全约束。

## 非目标

- 第一版不生成求职信、面试题或投递邮件。
- 第一版不抓取招聘网站，也不自动提交职位申请。
- 第一版不引入新的工作流节点类型或修改 runtime 调度器。
- 第一版不提供多套视觉主题，只提供一个可靠的单栏模板。
